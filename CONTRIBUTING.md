# Branchs
Toda branch deve ser nomeada com as tags referentes ao seu tipo.

1 - Feat: Nova funcionalidade ou adição de código no repositorio
2 - Fix: Correção de código ou bug não urgente
3 - Hotfix: Correção de código ou bug de carater urgente, precisa ser resolvido imediato.
4 - Release: Lançamento de nova versão do projet (Ex: v1.2)

# Commits

Todo commit deve seguir o padrão do commit conventionals.

1 - feat: Nova funcionalidade ou adição de código no repositorio
2 - fix: Correção de código ou bug não urgente
3 - hotfix: Correção de código ou bug de carater urgente, precisa ser resolvido imediato.
4 - docs: Adição de artefatos de documentação do projeto dentro do repositório.

# PR e Merge
Os merges devem ser feitos através de Pull Requests dentro do GitHub com a devida aprovação de outro desenvolvedor que colabore no projeto.
